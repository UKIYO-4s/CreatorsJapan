# PORTAL 最小要件

この文書は、`CreatorsJapan` 親 repo に置くポータルの最小要件を定義するための正本です。

## 目的

ポータルは、`記事/` と `コラム/` を横断して、いま何が進んでいて、次に何を触るべきかを 1 画面で把握するための運用ハブです。

この段階では、見た目の完成度よりも `状況把握` `導線` `更新しやすさ` を優先します。

## 対象ユーザー

- 自分
- 将来の共同作業者
- 引き継ぎ時の確認者

## MVP で必要なもの

### 1. 領域一覧

- `記事`
- `コラム`
- `共通 docs`
- `GitHub Project`

各領域に対して、次を表示する。

- 何を管理しているか
- 正本がどこか
- どの README を最初に見るか

### 2. 状態一覧

少なくとも次の状態を横断表示できること。

- `準備中`
- `進行中`
- `確認待ち`
- `公開待ち`
- `公開済み`
- `保留`

初期段階では、Markdown 台帳を手更新してもよい。

### 3. 次アクション

各領域ごとに、`次にやること` を 1 から 3 件見えるようにする。

初期ソースは以下を許容する。

- `MD運用台帳.md`
- 各 `README.md`
- GitHub Project の draft item

### 4. 入口リンク

最低限、以下へ 1 クリックで行けること。

- 親 repo README
- `記事/README.md`
- `コラム/README.md`
- `docs/SUBMODULE運用ルール.md`
- GitHub Project `CreatorsJapan Workspace`

## 今はやらないもの

- 認証
- DB
- 自動クロール
- リアルタイム同期
- 複雑な分析ダッシュボード
- KPI 集計の自動化

## データソース方針

初期段階では、`Markdown 正本` を最優先にする。

- 状態: 各 README
- 横断要約: `MD運用台帳.md`
- 実装ルール: `docs/*.md`
- タスク: GitHub Project

あとから必要なら、JSON 生成や GitHub API 連携を追加する。

## 情報設計

ポータルの最小構成は次の 4 ブロック。

1. 今日見るべきもの
2. 領域別ナビゲーション
3. 状態一覧
4. 次アクション

## 実装方針

- 親 repo の責務として `portal/` に置く
- まずは静的に始める
- データの正本は Markdown に残す
- 将来、必要なら Astro か軽量フロントエンドへ発展させる

## 完了条件

次を満たしたら MVP 着手準備完了とする。

- `portal/README.md` がある
- ポータルの目的と責務が README から分かる
- 表示すべき最小ブロックが定義されている
- 親 repo に置く理由が明文化されている
